# 阶段 0.6 Prologix 第三切片记录

日期：2026-08-14

结论：已完成显式配置的 Prologix GPIB-USB/GPIB-Ethernet 生产 Provider 和 Linux 无硬件纵向验证。该路径依据官方命令协议独立实现，不链接、加载或复制 GPL linux-gpib；TCP loopback 与 POSIX PTY 直接经过公共 C API 和生产 I/O 代码。真实 Prologix 控制器、GPIB 总线仪器与 Windows runtime 均未取得，因此保持 `NOT_TESTED`，不得把本记录描述为硬件互操作通过。

## 配置与 ABI

- 新增 RM 范围 `wrvisaSetPrologixController`，将一个 GPIB board 显式映射到串口路径或 TCP host/port；标准 `GPIB[board]::primary[::secondary]::INSTR` 不变。
- 40 字节 `wrvisa_prologix_controller_config_v1` 使用 `struct_size`、ABI 1.0、零 flags/保留字段，配置连接类型、TCP port、EOT 字节、1–3000 ms 控制器读取空闲 timeout 和最大 64 MiB 响应上限。
- 串口配置要求 `tcp_port == 0`，TCP 配置要求非零 port；无效结构尺寸、ABI、保留字段、连接类型、timeout 和大小均在 C ABI 边界拒绝。
- `wrvisaSetPrologixController` 是第 27 个公共导出，固定在新 `WRVISA_0.6` 节点；原有 0.1–0.5 符号不迁移。C/C++ 头检查冻结结构为 40 字节且为标准布局。

## 控制器边界

- 进程池以连接类型、原样 endpoint 字符串和 TCP port 为身份；相同身份跨 RM、board 和会话共享一个 controller，配置冲突返回 `VI_ERROR_RSRC_BUSY`。
- 共享 gate 覆盖地址选择、EOI 状态、命令/数据发送和完整响应排空，并让排队等待服从同一个 operation 绝对 deadline。DNS/IP 别名和串口符号链接不自动归并，部署必须统一 endpoint 拼写；跨进程仲裁不在本切片范围。
- 每次连接或恢复先发送 `++savecfg 0`，再固定 `mode 1`、`auto 0`、`eos 3`、EOT 与 `read_tmo_ms`，最后读取并验证 `++ver`；运行时地址和 send-end 切换不会写 EEPROM。
- 写入对 CR、LF、ESC 和 `+` 加 ESC 前缀，再以未转义 LF 结束控制器帧；主次地址分别使用 PAD 与 `96 + SAD`。
- `viRead` 先执行 `++read eoi` 并在释放 controller 前有界排空到配置的 EOT，再由通用 GPIB 会话提供终止符、EOI 和 read-ahead；读取缓存 discard 同时清理会话与 transport 已预取字节。selected device clear、group execute trigger 与 serial poll 分别映射到 `++clr`、`++trg` 和 `++spoll`。
- 超时、取消、连接错误、响应超限或协议边界错误会关闭通道；下一事务重连并完整初始化，未知控制器状态不会复用。

## 无硬件验证

- GCC 13.3 以 C++20、standalone Asio 1.38.2、`-fPIC` 和生产目标等价高告警参数手工编译全部生产源，附加 `-Werror` 通过；临时共享库的 ELF 精确导出门禁确认 27 项。
- `prologix_tests` 使用生产 TCP socket 和 loopback 控制器，经 `wrvisaSetPrologixController`、标准 GPIB 资源与公共 `vi*` 覆盖配置错误、无虚构发现、跨 RM/board 共享、主次地址、二进制发送转义、send-end、终止符/read-ahead、传输预取缓存 discard、serial poll、trigger、clear、并发事务、排队 timeout、响应超限、取消和重连初始化。
- `prologix_serial_tests` 使用生产 serial port 与 POSIX PTY，覆盖不存在路径、9600-8N1 打开、初始化、地址/EOI、特殊字节转义和 EOT 读取；通用 `gpib_tests` 与 C/C++ 公共头 smoke 也在同一生产对象集上通过。
- 通用 `gpib_tests` 与两个 Prologix 测试在 GCC ASan/UBSan/LSan（`detect_leaks=1`、遇错停止）下通过，无 Sanitizer 报告。
- MinGW-w64 GCC 13 编译全部生产源并链接 `prologix_tests.exe`；临时 DLL 的 PE 精确导出门禁确认 27 项。交叉产物未运行，不能替代 Windows 原生 runtime。
- `tools/validate_docs.py` 通过并映射 89 个第一方文件；`tools/validate_abi_history.py` 确认 6 个版本节点共 27 个符号；`git diff --check` 通过。
- 当前容器没有 CMake，无法把上述手工结果表述为完整 CTest、安装消费或全套 Sanitizer 复验；第一切片的历史完整门禁仍有效，但不能替代新增代码的缺失矩阵。

## 固有限制

- Prologix 只用一个未转义字节标记 GPIB EOI；仪器响应若包含同值字节就无法消歧。调用方必须选择不会出现在预期响应中的 EOT，本 Provider 不适合任意 8 位二进制响应。
- Provider 不扫描地址、不向 `viFindRsrc` 添加无法证明存在的仪器，也不实现 `GPIB::INTFC`、parallel poll、pass control、控制器网络发现或跨进程锁。
- TCP/PTY 模拟只证明主机实现与受控协议行为闭环；真实固件差异、USB 串口驱动、网络设备单客户端限制、总线电气和第三方仪器错误行为均为 `NOT_TESTED`。
