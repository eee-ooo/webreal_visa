# 阶段 0.3 Linux 实施与验收记录

日期：2026-08-11

结论：`webreal_visa 0.3.0` 的 VXI-11 与 HiSLIP 1.x Linux 客户端纵向切片已经实现，并以仓库内 loopback 协议模拟器完成验证。用户明确允许暂不运行 Windows 部分，因此本报告只判定“0.3 Linux 实现与验证完成”；Windows 原生、macOS 和真实仪器互操作均为 `NOT_TESTED`。

## Linux 验证

- Debug 与 Release 均构建共享/静态库和全部测试，CTest 均为 12/12；覆盖资源、核心、API、并发、TCP、串口、协议 codec、VXI-11、HiSLIP、C/C++ 头与文档门禁。
- ASan/UBSan 以 `halt_on_error=1` 运行同一测试集合，12/12 通过。
- 压力门禁发现并修复共享 runtime 最后引用在 worker 回调释放时自我 join 的低概率生命周期竞态；修复后 VXI-11/HiSLIP 各连续 200 轮通过，并发、TCP、ASRL、VXI-11 和 HiSLIP 五组再各连续 100 轮通过。
- 网络测试只绑定 loopback；串口测试只使用临时 POSIX PTY，不要求外部硬件，也不发送外部网络数据。
- 安装到临时前缀后，独立 C 消费工程以 `find_package(webreal_visa 0.3 CONFIG REQUIRED)` 构建，`mock_query` 1/1 运行通过。
- ELF 动态导出只允许 21 个标准 `vi*` 与两个项目扩展：`WRVISA_0.1` 标准函数、`WRVISA_0.2` 串口映射、`WRVISA_0.3` TCPIP 服务端口覆盖；版本节点继承关系已由 `readelf` 核对。

## 2026-08-12 无硬件复验

在没有真实仪器的 Linux x86-64 环境中，从当前工作区使用 GCC 13.3、临时隔离的 CMake 4.4.2/Ninja 1.13 和仓库锁定的 Asio 源码重新执行门禁，结果如下：

- Debug、Release 与 GCC `-fsanitize=address,undefined`（启用 leak detection）三套全量 CTest 均为 12/12；Sanitizer 没有报告泄漏、越界或未定义行为。
- Release 下 `concurrency_tests`、`tcp_tests`、`serial_tests`、`vxi11_tests`、`hislip_tests` 各以 `--repeat until-fail:500` 连续通过，共 2500 次；扩充后的 `api_tests` 与 `protocol_codec_tests` 各连续 1000 次通过。两组合计 4500 次测试进程调用，没有触发首次失败。
- 增加公共 API 的空参数、无效句柄、非法资源/模式、只读与不支持属性、缓冲区边界、终止参数、锁类型/access key、嵌套锁、状态描述和项目扩展参数测试；增加 XDR 截断/超限 opaque、RPC XID/截断/拒绝状态以及 HiSLIP 截断/超大长度测试。没有修改生产实现。
- gcov/gcovr 只统计第一方 `src/`：行覆盖由 71.6%（2957/4129）升至 73.8%（3046/4129），函数由 88.2%（398/451）升至 89.4%（403/451），分支由 59.1%（2095/3544）升至 62.1%（2201/3544）。`src/api/visa_api.cpp` 行覆盖由 55% 升至 66%，VXI-11 codec 由 93% 升至 97%。
- Release 临时安装、独立 `find_package(webreal_visa 0.3 CONFIG REQUIRED)` C 消费工程构建和 `mock_query` 1/1 运行通过；`readelf` 确认 21 个标准入口和两个扩展入口之外无第一方动态导出，0.1/0.2/0.3 节点正确继承。
- 所有网络测试只绑定 `127.0.0.1`，串口测试只使用 POSIX PTY；本轮没有访问仪器或外部网络。首次在受限沙箱内运行时 loopback socket 创建被系统策略拒绝，授予本机 socket 权限后同一二进制通过，因此不记为产品失败。

当前环境没有 Clang、Valgrind、clang-tidy/cppcheck，sudo 非交互安装也不可用，所以这些可选矩阵未执行；ThreadSanitizer 仍受既有容器运行时内存映射限制。以上结果增强 Linux 软件与受控协议行为证据，但不改变 Windows、macOS、真实串口电气行为和真实 VXI-11/HiSLIP 仪器互操作的 `NOT_TESTED` 状态。

## 协议与兼容边界

- VXI-11 使用 portmapper/core/abort 三个受控连接；取消通过 `device_abort` 并排空当前 RPC 响应，随后会话可复用。
- HiSLIP 使用同步和异步连接；取消/超时通过 AsyncDeviceClear/Interrupted/DeviceClearComplete 握手恢复，再允许后续请求。
- HiSLIP 只实现 1.x synchronized mode；overlap、HiSLIP 2/TLS/加密明确拒绝，不降级连接。
- VXI-11 共享 VISA 锁仍只在当前进程协调；HiSLIP 的共享与排他锁均映射到远端协议。
- `WR` HiSLIP vendor ID 尚未注册。正式互操作声明前必须按 IVI VPP-9 取得有效分配并以真实设备重测。

## 后续验收条件

进入真实 Windows runner 后，运行 Debug/Release、适用协议模拟器、安装消费和 PE 导出检查；至少选择一个 VXI-11 与一个 HiSLIP 真实设备建立厂商互操作记录。完成这些项目之前，0.3 只能标记为 Linux 侧完成，不得标记为跨平台或硬件完整验收。
