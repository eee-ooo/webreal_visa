# 阶段 0.6 linux-gpib 许可与 API 闸门记录

日期：2026-08-14

结论：第二切片已完成评审，但不实现 linux-gpib 生产 Provider。官方 4.3.7 用户态库的 API 能覆盖现有 GPIB Transport 所需的打开、异步读写、EOI、清除、触发、状态字、取消和关闭；其用户态库、公开头与实现同时处于 GPL 边界，且没有发现链接例外。按本项目既有 MIT 目标和强 copyleft 禁入政策，直接链接、延迟链接或 `dlopen` 均不被接受，因此本切片按预先约定停在通用 Provider 契约，不伪造生产支持。决策见 [`ADR-0011`](../decisions/0011-linux-gpib-license-boundary.md)。

## 固定来源

- 官方项目页：`https://linux-gpib.sourceforge.io/`，明确说明包包含 C 用户态库并采用 GNU GPL。
- 官方稳定发布：SourceForge `linux-gpib-4.3.7.tar.gz`；外层归档 SHA-256 为 `b3ff812606865c85b58b012a4218a6fe3b82d177c8c0abc795cb22db41f3ad68`。
- 外层归档中的 `linux-gpib-user-4.3.7.tar.gz` SHA-256 为 `9fadb8a063d7a83c753e428d87ad9677d8fb18ed5a61cb557898ae9b8a987f71`。
- 用户态 `COPYING` 是 GNU GPL version 2；`include/gpib/gpib_user.h` 标记 `GPL-2.0`，`include/gpib/ib.h` 及所查 `lib/*.c` 声明 GPL version 2 or later。没有复制这些文件到仓库。

## API 语义映射

| Transport 需求 | linux-gpib 4.3.7 候选 API | 评审结果 |
|---|---|---|
| 打开地址化设备 | `ibdev(board, pad, sad, tmo, eot, eos)` | board 与主地址可直接映射；无次地址传 `0`，有次地址传 `0x60 + secondary` |
| 异步读取/写入 | `ibrda` / `ibwrta` | 每个 descriptor 同时只允许一个异步操作；调用方缓冲必须保持到 resync 完成 |
| 等待完成 | `ibwait(ud, CMPL | TIMO)` | `CMPL` 才会 join 并同步异步结果；应读取 `AsyncIbsta`/`AsyncIberr`/`AsyncIbcntl` 避免混淆 wait 自身状态 |
| 取消 | `ibstop(ud)` | 实现取消内部 pthread 并 join；成功中止反而以 `ERR` 且 `EABO` 表示，必须特殊映射为本项目取消结果 |
| deadline | `ibtmo` 离散枚举 | 只有 10 µs 至 1000 s 的离散档位和无限等待，实际超时保证不早于档位；不能单独承担绝对 deadline |
| EOI/send-end | `END` 状态与 `ibeot`/`ibdev(..., eot, ...)` | 可表达读 EOI 与写末字节 EOI，但需要逐 operation 配置和恢复策略 |
| 控制能力 | `ibclr`、`ibtrg`、`ibrsp` | 分别对应 device clear、trigger、serial poll；错误通过线程局部 `ibsta`/`iberr` 读取 |
| 关闭 | `ibonl(ud, 0)` | 先停止并 join 异步操作，再关闭 handle 并释放 descriptor |

## 许可闸门

- 本项目政策把进程内动态链接、静态链接和显式 `dlopen` 视为同一依赖边界；三者均不采用。
- 不提交 linux-gpib 归档、许可证、头文件、常量副本、C API 函数表或模拟器，因为没有获准的生产适配目标需要这些构建材料。
- 不添加看似可用但永远不注册的 Provider；现有测试 Provider 已足以验证第一方 Transport/Session 契约。
- 未来若取得兼容授权，应重新固定获授权版本，并以第一方函数表模拟器验证错误映射、异步 buffer 生命周期、`ibstop` 竞态、离散 timeout 和 descriptor 关闭后复用。

## 验证与边界

- `tools/validate_docs.py` 与 `tools/validate_abi_history.py` 是本切片适用门禁；本切片没有生产代码、公共 ABI、CMake 目标或第三方分发材料变化。
- 既有 GPIB 第一切片仍由测试 Provider 证明公共 API 闭环；真实 linux-gpib、控制器、内核驱动、权限配置和总线仪器全部保持未实现或 `NOT_TESTED`。
- 本记录是工程依赖政策结论，不替代版权主体在正式发布前进行的法律审核。

## 下一步

推荐把 Prologix 作为独立的 `0.6` 第三切片候选：先决定标准 GPIB 资源到串口/TCP 控制器端点的显式配置方式，再评审命令模式、EOI/EOS、超时取消、控制能力缺口和多会话仲裁。NI-488.2 继续作为 Windows 专属独立切片，不与 Prologix 或 linux-gpib 结论混合。
