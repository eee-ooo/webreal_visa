# 阶段 0.4 Linux 无硬件兼容性加固记录

日期：2026-08-12

结论：`webreal_visa 0.4.0` 的 Linux 无硬件兼容性加固实现完成。VPP 资源属性查找子集、RM 范围资源 alias、标准可选输出以及 0.1–0.4 ABI 历史门禁均已实现并通过 Debug、Release 和 GCC ASan/UBSan/LSan；没有进入 USB、本机 GPIB、HiSLIP overlap/2.0/TLS 或硬件能力。0.4 新增 API 尚未在 Windows 原生重新运行，准确状态为 `NOT_TESTED`；既有 Windows 0.3 网络/协议证据继续有效。

## 设计边界

- Alias 是 `PROJECT_EXTENSION`，只存在于创建它的 RM 会话，不写注册表、配置文件或系统数据库。一个 canonical resource 在一个 RM 中只保留一个确定性 alias；重复配置覆盖旧映射，alias 不形成链，也不作为第二个物理资源枚举。
- 属性表达式先编译后求值；所有属性来自已规范化的资源描述符或标准默认值，`viFindRsrc` 不为查询属性打开网络/串口设备。当前子集仍为 `Partial`，未支持属性不能被写成“值未知所以不匹配”，而是明确拒绝整个表达式。
- 资源字符串匹配继续大小写不敏感；属性字符串比较按规范值执行精确比较。Alias 查找大小写不敏感，展开结果始终返回 canonical resource。
- 0.4 没有改变 VXI-11/HiSLIP/raw TCP 生产传输实现；传输故障用例的重新执行是回归证据，不是新增真实仪器互操作证据。

- GCC 13.3 Debug：全量 CTest 14/14（含文档、ABI 历史和精确导出门禁）。
- GCC 13.3 Release：全量 CTest 14/14；`resource_tests` 与 `api_tests` 各连续 100 轮通过。
- GCC ASan/UBSan/LSan Debug：`ASAN_OPTIONS=detect_leaks=1:halt_on_error=1`、`UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1`，全量 CTest 14/14。
- Release 全新安装与独立消费：`mock_query` 静态目标、`mock_query_shared` 共享目标 2/2；`libwebreal_visa.so` 精确导出 24 个命名符号。
