# 0.6 Linux CMake 收口验证记录

日期：2026-08-14
验证基线：`19b4242`（`feat(gpib): add Prologix controller provider`）

## 结论

当前 0.6 代码已在 Linux 完成此前缺失的完整 CMake 门禁。动态 libusb 1.0.30 启用时 Debug/Release 全量测试各为 22/22，显式关闭 libusb 的 Debug 为 21/21，GCC ASan/UBSan/LSan（`detect_leaks=1`）为 22/22；Release 的通用 GPIB、Prologix TCP loopback 和 Prologix POSIX PTY 三项测试各连续 1000/1000 轮通过。全新安装后的静态/共享纯 C 消费为 2/2，安装共享库精确导出 27 个公共符号、ABI 历史为 6 个版本节点，并确认运行时通过动态库边界加载 libusb。

这证明当前 Linux 无硬件软件范围已经收口，不证明真实 Prologix、GPIB 或 USB 器件可用，也不替代 Windows/macOS 原生运行。

## 环境与依赖

- Ubuntu 24.04.4 LTS x86_64，Linux 6.8.0-136-generic。
- GCC/G++ 13.3.0，GNU Make 4.3。
- CMake 3.28.3，使用 Ubuntu 官方软件包解压到 `/tmp`，未修改系统安装。
- standalone Asio 固定提交 `8806a6803cde7054c3049d3666d3ec36786568c5`；下载归档 SHA-256 为 `ca7f6c14f2bf91e61c7e81fb693f2f8fc86f93e85520d5fc7fd035d0f666bb35`，与仓库锁定值一致。
- 动态 libusb 1.0.30；`pkg-config` 报告 `1.0.30`，安装产物的 `ldd` 指向该动态库而非静态归档。
- 所有构建、安装和依赖暂存目录均位于 `/tmp/wrvisa-linux-validation` 或既有 `/tmp/libusb-1.0.30-install`；源码目录没有生成构建产物。

所有四套全量 CTest 均为首次运行通过，没有先失败后重试。

## 0.6 持续运行

Release 构建使用 CTest `--repeat until-fail:1000` 并行运行以下三项：

- `gpib_tests`：1000/1000。
- `prologix_tests`：1000/1000。
- `prologix_serial_tests`：1000/1000。

三项合计 3000 次测试进程调用，总用时 296.08 秒，无首次失败。覆盖范围包括厂商无关 GPIB 公共 API、Prologix TCP 端点仲裁/超时/取消/重连和 POSIX PTY 串口打开/初始化/I/O；仍只使用受控 loopback 与 PTY。

## 准确边界

- 没有真实 Prologix 控制器、GPIB 仪器或 USBTMC/USB488/RAW 设备，因此硬件、驱动、权限、总线电气和固件差异仍为 `NOT_TESTED`。
- Windows 0.4–0.6 原生 runtime、当前 27 项 PE 导出和安装消费没有在本轮运行；MinGW 交叉证据不能替代。
- macOS、远端 CI、Clang、Valgrind、clang-tidy/cppcheck 没有本轮结果；ThreadSanitizer 仍受当前容器运行时内存映射限制。GCC ASan/UBSan/LSan 不替代这些矩阵。
- 目标许可与依赖边界没有改变；linux-gpib 继续被 GPL 闸门拒绝，正式发布仍受版权主体未确定阻塞。

## 下一步

Linux 0.6 当前无硬件软件门禁不再是阻塞项。后续优先级转为真实 Prologix/GPIB 硬件矩阵和 Windows 0.4–0.6 原生复验；NI-488.2 继续保持为后续独立 Windows 切片，不混入本轮。
