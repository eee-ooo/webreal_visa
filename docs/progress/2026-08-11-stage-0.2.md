## Linux 验证

- 环境：GCC/G++ 13.3.0，CMake 4.1.0；工程继续声明 CMake 3.25+。
- Debug 与 Release：共享/静态库及全部测试构建成功；两套 CTest 均为 9/9，通过资源、核心、API、并发、TCP、串口、C/C++ 头和文档门禁。
- ASan + UBSan：9/9 通过，启用泄漏检测、未定义行为栈和遇错停止。
- Release 下 `concurrency_tests`、`tcp_tests`、`serial_tests` 各自连续 100 轮通过，共 300 次；覆盖真实传输取消与资源重复创建/销毁。
- 安装到临时前缀后，独立 C 工程以 `find_package(webreal_visa 0.2 CONFIG REQUIRED)` 构建 `mock_query` 与 `tcp_query`，模拟查询 1/1 运行通过。
- ELF 动态导出仅有 21 个 `vi*`、`wrvisaSetSerialPath` 与两个版本节点；原有函数位于 `WRVISA_0.1`，新扩展位于继承它的 `WRVISA_0.2`。
- 默认 FetchContent 路径实际从固定 codeload URL 下载、校验并完成 Release 构建；本地 `WRVISA_ASIO_SOURCE_DIR` 路径也用于全部主测试构建。
- 网络测试仅使用 loopback；串口测试仅使用临时 POSIX PTY，不要求外部硬件。

## Windows 验证

- x86_64-w64-mingw32 GCC/G++ 13.0.0 交叉工具链已成功构建 DLL、静态库和 Windows 适用测试。
- PE 导出表包含且仅包含 21 个 `vi*` 和 `wrvisaSetSerialPath` 共 22 个公共函数。
- Windows 包安装成功，独立 C 消费工程通过 `find_package(webreal_visa 0.2)` 生成 x86-64 PE `mock_query.exe` 与 `tcp_query.exe`。
- POSIX PTY 测试按平台条件不在 Windows 构建；Windows 串口发现和 COM10+ 路径逻辑已编译。
- 未在真实 Windows 上执行，因此 TCP、COM 枚举、Overlapped serial 和关闭/取消行为一律是 `NOT_TESTED`。

## 兼容与错误语义

- 语法合法但后端未实现的 TCPIP `INSTR`、GPIB 和 USB 仍返回 `VI_ERROR_NSUP_OPER`。
- raw TCP 不伪造 message-based clear、status byte 或 trigger，相关调用如实返回不支持。
- 超时/取消调用不提交用户缓冲区，返回计数为零；已经从流中取出的部分数据回到 read-ahead，供后续读取。
- 真实 close 先使句柄失效，再取消排队/进行中 operation 并关闭底层传输。
