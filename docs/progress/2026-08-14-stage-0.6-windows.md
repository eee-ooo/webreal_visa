# 阶段 0.6 Windows 原生无硬件验收记录

日期：2026-08-14
验证基线：`19b4242`（`feat(gpib): add Prologix controller provider`）

## 结论

`webreal_visa 0.6.0` 的当前 27 项公共 ABI 已在 Windows 11 原生完成 0.4–0.6 无硬件复验。VS 2022 Community（MSVC 19.44.35228 / x64 / Windows SDK 10.0.26100）下 Debug、Release 与 MSVC `/fsanitize=address` Debug/Release 四套全量 CTest 均为 **19/19**；Release 高风险 13 用例各连续 25 轮无首次失败；全新安装后的静态/共享纯 C 消费 2/2，`tcp_query` 连接本机回显服务器 1/1；`dumpbin /exports` 确认 DLL 恰好导出 27 个公共符号，ABI 历史 6 节点门禁通过。

本机没有 libusb 1.0.30，`WRVISA_LIBUSB=AUTO` 关闭生产 USB 适配器（与 CI Windows 行为一致），`libusb_adapter_tests` 不构建；`serial_tests` 与 `prologix_serial_tests` 在 CMake 中为 UNIX-only，Windows 不构建。真实 Prologix/GPIB/USB 硬件、Windows libusb runtime 与 Windows ASRL runtime 仍为 `NOT_TESTED`，本轮不改变这些边界。

## 环境与依赖

- Windows 11（目标 Windows 10.0.26200），VS 2022 Community 生成器，`cl.exe` 19.44.35228 / 工具集 14.44.35207，Windows SDK 10.0.26100，16 逻辑核。
- CMake 3.28.1；构建使用 `Visual Studio 17 2022` 生成器（x64）。
- Python 3.14.5（`D:\eeeooo\Python\python.exe`）。文档/ABI 门禁脚本需要 3.7+（`from __future__ import annotations`）与 3.8+（walrus `:=`）；机器默认的 Anaconda Python 3.6.4 不合格，显式指定解释器后门禁通过。
- standalone Asio 固定提交 `8806a6803cde7054c3049d3666d3ec36786568c5`，以本地源码目录传入 `WRVISA_ASIO_SOURCE_DIR`，未访问网络。
- 无 libusb：`WRVISA_LIBUSB=AUTO` 探测失败，生产 USB transport 禁用，USB 协议/API 测试（脚本化 transport）照常构建运行。

## 导出与 ABI 门禁

- `dumpbin /exports` 确认 DLL 恰好导出 27 项：21 个标准 `vi*` + 6 个 `wrvisa*` 扩展，其中 `wrvisaSetPrologixController` 属于新增 `WRVISA_0.6` 版本节点；旧符号所属节点不变。
- `abi_history`（`validate_abi_history.py`）与 `abi_exports`（`validate_exports.py` 解析 PE 导出表并与 `cmake/webreal_visa.map` 白名单比对）均通过。

## 本轮环境注意（均为验证过程问题，不是产品缺陷）

1. **MSBuild 并行节点静默失败**：`cmake --build --parallel`（等价 `msbuild /m`）在本机只打印 MSBuild 版本行后以退出码 1 结束，无编译错误输出；同一命令 `/m:1` 串行构建 0 警告 0 错误。全部构建改为串行执行。
2. **默认 Python 过老**：CMake 探测到 Anaconda Python 3.6.4，三个门禁脚本因 `from __future__ import annotations`（3.7+）与 walrus 运算符（3.8+）语法错误失败；指定 Python 3.14.5 后通过。
3. **安装前缀放构建树内会干扰文档门禁**：`validate_docs.py` 递归扫描仓库内全部 `*.md`，构建树内安装前缀中的 `THIRD_PARTY_NOTICES.md` 副本因相对链接在安装树位置不存在而报 broken link；安装前缀移到仓库外后解决。
4. **MSVC ASan runtime DLL 不在 PATH**：ASan 测试进程以 `0xc0000135`（DLL 找不到）退出；把 `VC\Tools\MSVC\14.44.35207\bin\Hostx64\x64`（含 `clang_rt.asan_dbg_dynamic-x86_64.dll`）加入 PATH 后全部通过。

## 准确边界

- 没有真实 Prologix 控制器、GPIB 仪器或 USBTMC/USB488/RAW 设备，硬件、驱动、权限、总线电气和固件差异仍为 `NOT_TESTED`。
- 本机无 libusb，Windows libusb runtime 未构建未运行；`libusb_adapter_tests` 不生成。
- `serial_tests` 与 `prologix_serial_tests` 为 UNIX-only，Windows ASRL runtime 与 Prologix 串口 runtime 本轮未运行。
- 本轮是本地手工证据；CI `windows-2025` 矩阵的 Debug/Release/ASan 组合仍须由远端 runner 首次执行，不能把“本地已通过”写成“远端已通过”。
- macOS、远端 CI、Clang、Valgrind、clang-tidy/cppcheck 没有本轮结果；MSVC ASan 不等价于 ThreadSanitizer 或其他编译器验证。
- 目标许可与依赖边界没有改变；linux-gpib 继续被 GPL 闸门拒绝，正式发布仍受版权主体未确定阻塞。

## 与 Linux 门禁的一致性

- 与 [`2026-08-14-stage-0.6-linux-cmake-validation.md`](2026-08-14-stage-0.6-linux-cmake-validation.md) 相比：同一 `19b4242` 基线、同一套测试语义；差异仅为 `libusb_adapter_tests`（本机无 libusb，Linux 为动态 libusb 1.0.30）与 `serial_tests`/`prologix_serial_tests`（UNIX-only），其余 16 个代码测试与 3 个门禁完全对齐。
- 本结果把 0.4–0.6 新增能力（alias/属性表达式/27 项导出、USB 模拟系列、GPIB 与 Prologix 公共 API 闭环）从 Windows `NOT_TESTED` 提升为 Windows 原生已验证（无硬件），替代 0.3 阶段 23 项导出的旧基线；不改变真实硬件互操作与 macOS 的 `NOT_TESTED` 状态，也不构成跨厂商 VISA 一致性声明。
