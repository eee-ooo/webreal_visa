# 阶段 0.5 USB RAW 切片记录

日期：2026-08-13

结论：第五个无硬件 USB 切片已完成。项目以两个 0.5 `wrvisa*` C ABI 扩展冻结 RM 范围、版本化 RAW 配置和端点零 control 契约，并将配置后的 bulk/interrupt 端点接入标准同步 `viRead`/`viWrite`。生产 libusb 适配器、测试 provider 和脚本化 transport 均覆盖 RAW；INSTR 与 RAW 可共享同一物理 interface claim。全部设备端证据仍来自受控模拟，本机没有可验证目标，因此真实 USBTMC/USB488/RAW 硬件、驱动/权限组合及 Windows libusb runtime 保持 `NOT_TESTED`，0.5 不标记硬件验收完成。

## 公共契约

- `wrvisa_usb_raw_config_v1` 固定为 32 字节，包含 `struct_size`、ABI 1.0、alternate setting、读写传输类型与端点、flags 和保留字段。当前类型为 `NONE`、`BULK`、`INTERRUPT`；未知类型、方向错误、零号非 control 端点、非零 flags/保留字段、未来 minor 或错误 major 均明确拒绝。
- `wrvisaSetUsbRawConfig` 只接受 USB `RAW` 资源，将配置按 alias 解析后的 canonical name 保存到当前 RM。配置是打开前契约；未配置的 `viOpen` 返回 `VI_ERROR_INTF_NUM_NCONFIG`，后续修改不改变已打开会话。
- `wrvisa_usb_control_request_v1` 同样固定为 32 字节和 ABI 1.0，承载 USB setup packet 的 `bmRequestType`、`bRequest`、`wValue`、`wIndex`。`wrvisaUsbControlTransfer` 只在 RAW 后端执行端点零 IN/OUT，方向取自 bit 7，长度不超过 16 位 `wLength`，成功字节数由 `retCnt` 返回。
- 新能力全部使用 0.5 `WRVISA_0.5` 版本节点中的 `wrvisaSetUsbRawConfig` 与 `wrvisaUsbControlTransfer`，没有新增非标准 `vi*`。旧 0.1–0.4 的 24 个符号不迁移节点；当前精确导出为 26 项。

## RAW 会话与并发

- `UsbRawBackendSession` 在构造时取得 transport interface 信息，并在每次 I/O 前验证 alternate setting、端点方向与 bulk/interrupt 类型完全匹配；provider 或 transport 不能用近似端点悄悄代替配置。
- `viRead` 支持 bulk-IN 或 interrupt-IN，沿用公共终止符和 read-ahead 语义；`viWrite` 支持 bulk-OUT 或 interrupt-OUT。`NONE` 可创建只读、只写或 control-only 会话，不支持方向明确返回 `VI_ERROR_NSUP_OPER`。
- 后端先写内部容器，只有成功赢得 operation 一次完成竞争后才提交用户缓冲与计数；取消、超时、关闭或连接丢失返回零字节，已接收但尚未提交的读取数据回到 read-ahead。
- RAW read、write 和 control 使用独立会话锁；libusb 连接以 active transfer 集合跟踪并发方向，取消/关闭可对每个 transfer 发出 cancel，并等待 callback 后再释放传输对象和缓冲。
- `viClear` 对配置的非零读写端点执行 halt clear；输入 discard 清理 RAW read-ahead。RAW 不伪造 USBTMC 状态字或 trigger 能力。

## Provider 与生产适配器

- provider 注册表新增 RAW 打开入口。路由仍按注册顺序；一个 provider 返回的失败诊断会暂存而不阻止后续 provider 成功处理，全部失败时返回最早诊断，非法“成功但无 transport”立即转为系统错误。
- 内建 libusb 发现为 active configuration 中每个 interface 生成 RAW 身份，不以 USBTMC class 限制通用 RAW；打开时选择指定 alternate setting，并严格匹配配置的端点地址、方向和 bulk/interrupt descriptor 类型。
- 同一 VID/PID/serial/interface 的 INSTR 与 RAW 身份使用同一连接 key、handle、claim、设备代次与热拔出状态。若两个会话要求不同 alternate setting，第二次打开返回 busy，避免对活动 interface 隐式改档。
- 生产适配器增加异步 control-OUT 与 interrupt-OUT；clear-halt 接受本会话选择的 bulk 或 interrupt 端点。所有 transfer 继续使用 operation 剩余绝对 deadline 和 callback 生命周期。

## 无硬件验证

- `usb_raw_tests` 以脚本化 transport 覆盖 bulk/interrupt 双向 I/O、终止符/read-ahead、control IN/OUT、halt clear、输入 discard、取消通知、关闭、alternate setting 不匹配与 `NONE` 方向。
- `usb_api_tests` 经公共 C ABI 覆盖未配置打开、32 字节结构、版本/保留字段/类型/端点方向/16 位 control 长度错误、alias 后配置、bulk I/O、端点零 IN/OUT、非 RAW 会话不支持、取消、INSTR/RAW 共享 claim，以及 provider 失败后继续路由。
- `libusb_provider_tests` 覆盖 vendor interface 的 bulk/interrupt alternate setting 与端点精确选择；`libusb_adapter_tests` 经生产代码覆盖 RAW 发现、与两个 INSTR 会话共享一次 claim、bulk 和 interrupt 双向数据、control IN/OUT、异步 RAW read cancel callback、取消后复用，以及会话关闭不提前 release。
- C11/C++20 头门禁检查两个公共结构均为 32 字节、C++ 标准布局并引用两个新函数；ABI 历史和动态导出门禁要求两个符号只属于 `WRVISA_0.5`。

## 验证结果

- GCC 13.3、libusb 启用：Debug/Release 完整 CTest 各 19/19；GCC ASan/UBSan/LSan（`detect_leaks=1`、遇错停止）19/19，无 Sanitizer 报告。
- `WRVISA_LIBUSB=OFF` Debug 全量 18/18，证明 RAW 会话和公共错误契约不依赖生产适配器存在。
- Release `usb_tests`、`usb_raw_tests`、`usb_api_tests` 与 `libusb_provider_tests` 各连续 1000 轮；含 INSTR/RAW 的 `libusb_adapter_tests` 连续 100 轮，无首次失败。
- 压力过程中额外 5000 轮 `usb_api_tests` 捕获到测试同步以 Session operation 计数近似 transport 已进入阻塞读的偶发窗口；模拟设备改为显式报告 bulk-IN 已挂起后最终 5000/5000 通过。修改只收紧测试观察点，不放宽取消状态、返回计数或复用断言。
- Release 全新安装后独立纯 C 静态/共享消费 2/2；ABI 历史与精确导出门禁通过，ELF 恰好导出 26 项。
- MinGW-w64 GCC 13、Release、`WRVISA_LIBUSB=OFF` 交叉编译全部库与测试目标；PE 精确导出门禁为 26 项。未运行这些 `.exe`，该结果不能记为 Windows 原生 runtime 或 libusb 通过。

## 下一步

- 0.5 不再扩展无硬件 USB 功能；保持 GPIB、HiSLIP overlap/2.0/TLS、动态插件加载和异步 job API 在范围之外。
- 可获得 Windows 原生环境时，重跑 0.4/0.5 新增公共 API、libusb 模拟适配器、MSVC Debug/Release/ASan、安装消费和 26 项 PE 导出。
- 硬件到位后建立独立验收记录，分别覆盖 USBTMC、USB488 和至少一个 RAW bulk/interrupt/control 设备的枚举、权限/驱动、claim、超时/取消、拔出与重连。本报告的模拟结果不得作为硬件通过证据。
