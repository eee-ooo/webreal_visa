## 验证记录

### Ubuntu 原生

环境：Ubuntu 24.04 系列工具链，GCC/G++ 13.3.0；临时使用 CMake 4.1.0 验证项目声明的 CMake 3.25+ 语法。

- Debug 与 Release 配置均成功构建共享库、静态库和全部测试。
- 两种配置的 CTest 均为 7/7 通过，包括资源、核心、API、并发、C/C++ 头和文档一致性；C11 smoke test 直接链接共享库，其余核心测试覆盖静态库。
- 并发用例连续重复 500 次通过。该压力验证曾捕获取消与条件变量之间的低概率丢失唤醒；读取等待和锁等待现均以对应互斥量同步取消通知，并在修复后重新完成全部构建与测试。
- ASan + UBSan：7/7 通过，启用泄漏检查与遇错停止。
- 安装到临时前缀后，独立 C 工程通过 `find_package(webreal_visa 0.1 CONFIG REQUIRED)` 构建并运行；`mock_query` 1/1 通过。
- `nm -D` 验证 ELF 动态符号仅含版本节点与 21 个白名单 `vi*` 符号，没有内部 STL/C++ ABI 泄漏。

### Windows 配置

环境：x86_64-w64-mingw32 GCC/G++ 13.0.0 交叉工具链。

- Release 配置成功构建 DLL、静态库、六个 C/C++ 测试可执行文件。
- PE 导出表包含且仅包含 21 个首批 `vi*` 符号。
- 成功安装 Windows 包，并由独立 C 消费工程生成 x86-64 PE `mock_query.exe`。
- 由于当前主机不是 Windows，这些 PE 文件没有本机运行；真实 Windows 行为由 `.github/workflows/build.yml` 的 `windows-2025` Debug/Release 门禁负责，当前仓库尚未推送，远端 CI 未执行。

### 已知验证限制

ThreadSanitizer 二进制可构建，但在当前容器启动即报告 `unexpected memory mapping`，所有受测程序都在进入项目代码前失败，因此不能将其记为代码测试失败或通过。并发正确性当前由确定性的 active-operation 同步测试、500 次重复压力测试与 ASan/UBSan 覆盖；后续应在兼容的原生 Linux runner 增加 TSan 门禁。

## 许可证结论

- 项目目标许可是 MIT，版权主体仍为 `[TBD_COPYRIGHT_HOLDER]`，因此没有生成正式 `LICENSE`，也未制作发行包。
- `0.1` 运行时没有第三方依赖。
- PyVISA/pyvisa-py 为 MIT，仅作思想对照；OpenVisa 在已核对提交上为 LGPL-3.0-or-later，只作架构对照，未复制、修改或链接。
- CI 唯一外部 action 固定到 `actions/checkout` v6.0.2 的精确提交。

## 未实现（不是遗留失败）

- 真实 TCP、串口、USB、GPIB、HiSLIP、VXI-11 和厂商 VISA 后端。
- 同主机跨进程锁与远端协议锁。
- Find 属性过滤表达式、完整 VISA 资源/别名集合、异步公共 API 和事件。
- 稳定版 ABI 兼容承诺、厂商/系统 VISA 二进制适配层和公开发行物。

以上项目属于后续阶段，均在兼容矩阵中明确标记，不应视为 `0.1` 已支持能力。
