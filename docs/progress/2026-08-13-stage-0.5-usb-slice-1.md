# 阶段 0.5 USB 首个协议/会话切片记录

日期：2026-08-13

结论：用户已授权进入 `webreal_visa 0.5` USB 阶段，首个无硬件协议/会话切片完成。该切片建立 USB `INSTR`/`RAW` 资源身份、可替换 `UsbTransport` 契约、USBTMC DEV_DEP 编解码和脚本化 transport 会话测试；Debug、Release 与 GCC ASan/UBSan/LSan 全量均为 15/15。0.5 整体仍在进行中：公共 `viOpen` 尚未路由到 USB、真实 libusb 适配器和枚举/claim 尚未实现，USB488 clear/abort/trigger/status 与通用 RAW I/O 也未完成，因此不能宣称 USB 可连接或硬件已验证。

## 已完成

- 工程版本推进为 `0.5.0`；既有 24 个公共符号及其 0.1–0.4 版本节点不变，没有新增导出 ABI。
- `ResourceDescriptor` 新增 USB VID、PID、序列号和 USB 接口号；`ResourceKind` 明确区分标准 `usb_instr` 与事实扩展 `usb_raw`。
- USB 解析支持省略/显式接口号以及 `INSTR`/`RAW` 资源类，规范化输出固定四位十六进制 VID/PID并保留 VISA board 与 USB interface 的不同含义。
- 新增不含 libusb 类型的 `UsbTransport` 契约，隔离 bulk I/O、控制能力、取消和关闭。
- 新增 USBTMC 12 字节 DEV_DEP 消息与读取请求编码/解码，校验非零 bTag、反码、保留字段、小端长度、属性、64 MiB 上限、精确 payload 和四字节零填充。
- 新增 `UsbTmcBackendSession`：支持消息写入、请求式读取、bTag 轮转、EOM、终止符、read-ahead、失败部分数据回收、取消转发和 clear/status/trigger 能力委派。
- 新增脚本化 transport 测试，未把模拟设备逻辑放入生产 USB transport。

## 验证

- GCC 13.3 Debug：全量 CTest 15/15，包括资源、API、并发、raw TCP、ASRL、VXI-11、HiSLIP、USBTMC、C/C++ 头、文档、ABI 历史与精确导出。
- GCC 13.3 Release：全量 CTest 15/15。
- GCC ASan/UBSan/LSan Debug：`detect_leaks=1`、遇错停止，全量 15/15；无 Sanitizer 报告。
- Release `usb_tests` 连续 1000 轮通过，无首次失败。
- Release 安装到全新临时前缀后，独立纯 C 静态/共享消费目标 2/2；`find_package(webreal_visa 0.5 CONFIG REQUIRED)`、0.5 模拟版本响应和安装后动态库均验证通过。
- 初次在受限沙箱运行时，TCP/VXI-11/HiSLIP 测试因本机 socket 创建被策略拒绝；在只允许 loopback socket 的权限下同一构建全绿，不记为产品失败。

## 依赖与许可

首个切片没有引入或链接新第三方依赖。本机存在 `libusb-1.0.so.0` 运行库，但没有开发头和 `libusb-1.0.pc`。ADR-0009 选择官方稳定标签 1.0.30 作为后续真实适配器候选，正式接入前仍需固定完整来源与归档 SHA-256、保留 LGPL-2.1-or-later 文本并验证动态链接/安装消费边界。

## 未完成与下一步

- 实现共享 USB 设备/接口仲裁、claim/release、连接代次和拔出失效。
- 将 USB `INSTR` 从公共 `viOpen` 路由到真实 USBTMC transport；补异步 bulk transfer、deadline 和 callback 完成后的安全取消。

- 实现 USB RAW 的显式 endpoint/control 配置和会话；其 `RAW` 名称继续标记为事实扩展。
- 在 Linux/Windows 原生重跑，并在有硬件时记录 VID/PID、驱动、固件和测试结果；在此之前 USB 硬件状态保持 `NOT_TESTED`。
