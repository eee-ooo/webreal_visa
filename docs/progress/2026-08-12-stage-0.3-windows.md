# 阶段 0.3 Windows 原生无硬件验收记录

日期：2026-08-12

结论：`webreal_visa 0.3.0` 的 Windows 11 原生（MSVC 14.44.35207 / x64 / Windows SDK 10.0.26100）网络/协议无硬件门禁完成。Debug、Release 与 MSVC ASan Debug/Release 全量 CTest 均为 11/11，安装消费与 DLL 导出门禁通过，Release 稳定性压测无首次失败。本轮修复了 Windows async connect 测试时序假设和共享库导入库安装问题，未修改生产传输实现。Windows ASRL runtime、真实仪器互操作与 macOS 仍为 `NOT_TESTED`。

## Windows 验证

- 使用 VS 2022 Community（MSVC 19.44.35207、Windows SDK 10.0.26100）与仓库锁定的 Asio 1.38.2 源码（SHA-256 与 CMake `URL_HASH` 一致）配置构建；CI 对应矩阵为 `windows-2025`。
- Debug 与 Release CTest 均为 11/11，覆盖资源、核心、API、并发、raw TCP、协议 codec、VXI-11、HiSLIP、C/C++ 头与文档门禁。`tcp_tests` 在 Windows 上耗时约 2.4s，多出部分即拒绝时序等待（见下）。
- MSVC `/fsanitize=address` 的 Debug 与 Release 全量均为 11/11，未报告地址类内存错误；ASan 运行时由 MSVC 自动随构建产物部署。未执行与 Linux LSan 等价的独立泄漏门禁，不能把本结果表述为 Windows 泄漏检查通过。四象限（Debug/Release × 有/无 ASan）全绿。
- Release 稳定性压测：`concurrency_tests`、`tcp_tests`、`vxi11_tests`、`hislip_tests` 各连续 500 轮，`api_tests`、`protocol_codec_tests` 各连续 1000 轮，共 4000 次测试进程调用无首次失败。
- Release 安装到临时前缀；独立 C 消费工程（`examples/`，纯 C 源码、C++ linker）构建 `mock_query`、`tcp_query` 成功，前者 1/1 运行通过，后者连接本机 Python 回显服务器完成 `*IDN?` 写读往返。
- `dumpbin /exports` 核对 DLL：导出集合与 Linux `webreal_visa.map` 完全一致（21 个 `vi*` + 两个 `wrvisa*` 扩展），无第一方额外符号泄漏。

## 2026-08-12 收口与持续门禁

- 新增跨平台 `tools/validate_exports.py`，从 `cmake/webreal_visa.map` 读取唯一公开符号白名单，直接解析 PE 导出表或使用 `readelf` 检查 ELF；作为 CTest 的 `abi_exports` 自动检查构建产物。
- `examples/` 同时构建并运行静态 `mock_query` 与共享 `mock_query_shared`；Windows 会把安装后的 DLL 复制到测试程序旁，避免依赖开发机 `PATH`，从而持续覆盖导入库安装和 `IMPORTED_IMPLIB`。
- GitHub Actions 保留 Linux/Windows Debug/Release 主矩阵，Release 对高风险用例执行 `until-fail:25` 轻量压力；另增加 Linux GCC ASan/UBSan 和 Windows MSVC ASan Debug/Release 矩阵。
- 收口改动已在 Linux Release 与 ASan/UBSan 环境各通过 13/13；全新安装前缀下静态/共享消费 2/2，CI 同款 7 个用例各连续 25 轮通过。现有 Windows Release DLL 也已由新增脚本独立复核为恰好 23 个命名导出。工作流 YAML 已完成本地语法解析，但新增 CI 组合仍须由远端 runner 首次执行，不能把“已定义”写成“远端已通过”。
- 本报告的 4000 次人工压力结论来自阶段执行摘要；逐轮原始 transcript 未保留，因此不把次数本身作为唯一验收证据。后续持续压力由 CI 日志保存，较长的 500/1000 轮阶段压力应同时归档命令与摘要。

## Windows 专属问题：async connect 拒绝时序

测试 `tcp_tests` 在 Windows 上首轮失败，根因不是生产代码，而是测试对平台时序的假设：

- 测试在 Linux 语义下以 1000ms 打开超时断言"连接本机已关闭端口返回 `VI_ERROR_RSRC_NFOUND`"。Linux 上 SYN 到关闭端口立即 RST，refusal 即时到达。
- Windows 上同一场景：同步 `connect()` 立即返回 `WSAECONNREFUSED`（10061），但 `asio::async_connect` 的 select-reactor 路径要到约 2048ms（实测 5 次：2044–2049ms，两个 SYN 重传窗口）才上报 refusal。1000ms deadline 先触发，`viOpen` 返回 `VI_ERROR_TMO`。
- 库行为本身正确：`map_connect_error` 对 10061 映射 `VI_ERROR_RSRC_NFOUND`，超时映射 `VI_ERROR_TMO`，两种结果都是合法的 VISA 语义。修正是测试侧：`_WIN32` 下打开超时放宽到 5000ms，断言保持 `VI_ERROR_RSRC_NFOUND`，并在测试内注释说明平台差异。
- 该测试此前只在 Linux 跑过；`windows-2025` CI 矩阵若不修同样会红。生产实现零改动。

## Windows 专属问题：共享库导入库未随安装分发

安装消费验证时发现第二个 Windows 专属缺口，属于打包问题而非运行问题：

- `install(TARGETS webreal_visa_shared ...)` 只声明了 `LIBRARY` 与 `RUNTIME` 目的地；Windows 上 DLL 的导入库（`.lib`）属于 `ARCHIVE` 产物，未声明 `ARCHIVE DESTINATION`，因此安装树只有 `bin/webreal_visa.dll` 与 `lib/webreal_visa_static.lib`，没有 `lib/webreal_visa.lib`，导出目标也缺少 `IMPORTED_IMPLIB`。`find_package` 后链接 `webreal_visa::visa`（共享目标）的 Windows 消费者会在链接阶段失败。
- 此前门禁只覆盖静态目标消费（`examples/` 消费工程与 CI 均链接 `webreal_visa::visa_static`），构建树内共享目标（`c_header_smoke`）用的是树内导入库，因此该缺口在 Linux 与既有 Windows CI 中均不可见。
- 修复：`install()` 增加 `ARCHIVE DESTINATION ${CMAKE_INSTALL_LIBDIR}`（非 Windows 平台无副作用）。修复后 `lib/webreal_visa.lib` 随安装分发，导出目标带 `IMPORTED_IMPLIB_RELEASE`，共享目标消费工程构建并运行 1/1。

## 环境与边界说明

- 本轮未执行的项目同 Linux 记录：无 Clang/Valgrind/clang-tidy/cppcheck 全矩阵、无 ThreadSanitizer；MSVC ASan 不等价于 ThreadSanitizer 或其他编译器验证。
- 无硬件：VXI-11/HiSLIP 只与仓库内受控 loopback 模拟器互操作；真实仪器、不同厂商错误行为、Windows 真实串口电气行为均为 `NOT_TESTED`。
- `serial_tests` 在 CMake 中为 `if(UNIX)` 条件构建，Windows 原生未运行串口测试；`wrvisaSetSerialPath` 与 ASRL 后端代码在 Windows 参与编译，但不宣称 Windows 串口验证。
- 本机环境注意：Git Bash 的 MSYS 路径转换会把 `/fsanitize=address` 一类以斜杠开头的 MSVC 旗标误当作路径，配置时需禁用转换；中文源文件在 GBK 代码页（936）下可能触发 C4819 续行陷阱，均属于本机工具链操作问题，不是产品缺陷。
- HiSLIP 仍只实现 1.x 同步模式；overlap、HiSLIP 2、TLS/加密与 mDNS 发现未实现。`WR` vendor ID 仍为临时值，未按 IVI VPP-9 注册。

## 与 Linux 门禁的一致性

- 与 `2026-08-11-stage-0.3-linux.md` 相比，Windows 侧验证了同套 loopback 模拟器、同套 CTest 用例（除 UNIX-only 串口测试）与相同的导出边界；发现并修复的拒绝时序差异属于 Windows TCP 栈 + asio select-reactor 的确定性行为（连续 5 次采样 2044–2049ms），已记录在测试注释中。
- 结果增强 Windows 软件栈与受控协议行为证据，不改变真实仪器互操作与 macOS 的 `NOT_TESTED` 状态，也不构成跨厂商 VISA 一致性声明。
